# Preserve nonzero exit for failed agy oneshot runs

**Date:** 2026-07-16 11:51
**Files:** hermes_cli/oneshot.py, tests/hermes_cli/test_agy_oneshot_e2e.py
**Severity:** medium

## Problem

`hermes --provider agy --oneshot ...` returned exit code 0 when the managed `agy` process exited with code 23. The agent exposed an API failure summary as nonempty stdout, and the generic oneshot contract treated any nonempty response as success.

## Root Cause

Oneshot intentionally permits a failed ordinary provider run to return 0 when it produces a usable error summary. That legacy rule did not account for providers marked fail-closed, where a provider failure must remain a machine-detectable process failure even when diagnostic text is available.

## Solution

The oneshot exit decision now checks the resolved route's fail-closed policy. Failed or partial fail-closed runs return code 2 while preserving their diagnostic stdout. The run result is annotated with the resolved provider and base URL so aliases and process URLs use the same centralized route policy.

## Prevention

- Treat process exit status and diagnostic response text as separate contracts.
- Exercise real CLI subprocess paths for provider adapters, not only mocked client calls.
- In fail-closed tests, configure a reachable fallback sentinel and assert it receives no requests.
