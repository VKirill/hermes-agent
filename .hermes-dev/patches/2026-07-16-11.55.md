# Agy tool-call contract and provider discovery parity

**Date:** 2026-07-16 11:55
**Files:** agent/agy_cli_client.py, hermes_cli/auth.py, hermes_cli/main.py, hermes_cli/model_setup_flows.py, hermes_cli/models.py, tests/agent/test_agy_cli_client.py, tests/hermes_cli/test_agy_provider.py, tests/hermes_cli/test_model_provider_persistence.py, tests/run_agent/test_agy_client_integration.py
**Severity:** high

## Problem

The keyless `agy` backend returned `<tool_call>` output as ordinary assistant text with `finish_reason="stop"`, so Hermes never executed requested tools. The provider was also absent from `CANONICAL_PROVIDERS`, which excluded it from `hermes model`, Desktop/TUI provider catalogs, and model persistence dispatch. Antigravity aliases were misclassified as Copilot ACP during status checks.

## Root Cause

The external-process adapter exposed tool schemas only as reference data and never translated agy output back into the OpenAI-compatible response contract consumed by the Hermes conversation loop. Separately, automatic provider discovery intentionally skips non-API-key providers because they need bespoke setup UX; adding the `agy` profile therefore could not add it to the canonical picker by itself. Alias registry entries share a canonical `ProviderConfig`, but status branching compared the caller-supplied alias instead of its canonical `id`.

## Solution

The agy prompt now carries explicit OpenAI-shaped tool-call instructions and `tool_choice`; valid `<tool_call>` blocks are parsed into structured tool calls with `finish_reason="tool_calls"`. A full AgyCLIClient→AIAgent regression proves the call reaches Hermes tool execution. The canonical provider list and a dedicated keyless agy model flow now persist provider, model, marker URL, and API mode. External-process profiles can expose `fallback_models`, and status/credential paths branch on the canonical `ProviderConfig.id`.

## Prevention

- Every OpenAI-compatible provider adapter must test both plain text and structured tool-call responses through the real conversation loop.
- New non-API-key provider profiles require an explicit canonical picker entry plus provider-specific setup dispatch; profile registration alone is insufficient by design.
- Any branch on provider identity after registry lookup must use the canonical config/profile id, not the input alias.
- Provider catalog tests should assert parity relationships across CLI, TUI, and Desktop rather than snapshotting provider counts.
