# External-process providers were omitted from model and auth surfaces

**Date:** 2026-07-16 13:05
**Files:** hermes_cli/models.py, hermes_cli/model_switch.py, hermes_cli/auth.py, hermes_cli/auth_commands.py, hermes_cli/web_server.py
**Severity:** high

## Problem

An installed keyless `agy` provider was missing from authenticated provider inventories. TUI and Desktop model options received an empty unauthenticated canonical skeleton, provider aliases were not recognized by the model parser, and the Desktop Accounts card launched `hermes auth add agy`, which incorrectly requested and persisted an API key.

## Root Cause

Three independently maintained provider views had diverged from the provider profile registry:

- model inventory treated credentials as API-key/auth-store state plus an AWS special case, so an external process could never satisfy availability;
- `hermes_cli.models` maintained a static alias table separate from plugin profile aliases;
- generic Accounts cards assumed every account provider could be configured through `hermes auth add`, while that command defaulted every non-OAuth provider to API-key auth.

The structural presence of an executable was also exposed as `logged_in` without identifying that this was only process availability, not a verified private auth session.

## Solution

External-process inventory now uses the canonical auth-status dispatcher and obtains model IDs through the existing cached provider-model resolver. Provider profile aliases are merged into the model parser's alias map. External-process auth-add attempts fail before pool loading or mutation, and the agy Desktop card launches `agy` directly. Status now exposes `available`, `auth_verified=false`, and `status_basis=process_available` while preserving the compatibility `logged_in` field.

## Prevention

- Derive provider aliases and auth behavior from `ProviderProfile`/`PROVIDER_REGISTRY` rather than duplicating provider-specific assumptions.
- Treat availability, configuration, and verified authentication as separate states for external processes.
- Add behavior regressions for every shared inventory consumer (CLI picker, TUI JSON-RPC, Desktop REST), alias parsing/listing, persistence, and credential mutation boundaries.
