# Managed agy cancellation and completed-workspace cleanup

**Date:** 2026-07-16 13:01
**Files:** agent/agy_cli_client.py, tests/agent/test_agy_cli_client.py
**Severity:** critical

## Problem

Cancelling `AsyncAgyCLIClient.create()` cancelled only the asyncio waiter while the thread-backed `agy` child continued running and could perform a late side effect. `AgyCLIClient.close()` tracked only one `_active_process`, so with `max_parallel > 1` another child could survive close. Completed request workspaces were cleaned only when a new client initialized, allowing a long-lived client to accumulate one directory per request.

## Root Cause

The async facade delegated to `asyncio.to_thread()` without an ownership token or cancellation bridge. A single mutable process slot also assumed serial execution even though SQLite permits multiple concurrent leases. Workspace retention was tied to startup maintenance rather than request completion, and cleanup used a running-request snapshot taken outside the database write lock, leaving a race where a newly acquired active workspace could be mistaken for garbage.

## Solution

Each async request now owns a cancellation event that is registered with its concrete child process. Cancellation signals the event, performs terminate→kill→wait for only that request, and waits for the worker thread to release its lease before re-raising `CancelledError`. The client stores every active process in a lock-protected registry, removes the exact process in `finally`, and closes all registered children.

Workspace cleanup now runs after success and failure, takes a `BEGIN IMMEDIATE` lock while reading active request IDs and deleting completed directories, preserves active workspaces, and treats runtime cleanup errors as logged best-effort failures so they cannot mask the request result. A failed private prompt unlink is recovered by removal of its completed workspace.

## Prevention

- Thread-backed async subprocess adapters need an explicit per-call cancellation token and must wait for worker cleanup before surfacing cancellation.
- Process ownership must be a collection whenever configured concurrency can exceed one; cleanup must remove the exact process object.
- Filesystem garbage collection coordinated by database leases must hold the lease write lock across the active snapshot and deletion.
- Test cancellation and close with observable late side effects, not only task/thread completion.
- Test cleanup in a single long-lived client and inject prompt-unlink failures.
