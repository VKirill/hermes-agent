# Legacy TUI runtime shim weakened agy fail-closed routing

**Date:** 2026-07-16 13:25
**Files:** tui_gateway/server.py, tests/test_tui_gateway_server.py
**Severity:** high

## Problem

When an older embedder supplied `hermes_cli.runtime_provider.resolve_runtime_provider` without the newer `provider_requires_fail_closed` helper, the TUI compatibility shim recognized only the literal requested provider `agy` and an `agy://` base URL. Requests through the `antigravity` alias or `requested=auto` with `AuthError(provider="agy")` activated the configured remote fallback chain instead of preserving the local process boundary.

## Root Cause

The compatibility implementation duplicated only the narrowest part of the shared runtime policy. It discarded the structured provider identity carried by `AuthError`, did not resolve provider aliases or profile-owned `fail_closed` policy, and treated classification failure as permission to fall back. The main runtime resolver was safe, but the older-runtime seam silently implemented a weaker security contract.

## Solution

The shim now evaluates `agy://` first, considers both `AuthError.provider` and the requested provider, recognizes canonical agy identities, and resolves every remaining candidate through the provider registry so aliases and any profile with `fail_closed=true` retain their policy. Registry import or lookup failures with a provider candidate now refuse fallback and emit bounded `[FIX:agy-tui-fail-closed]` warning evidence. Adversarial regressions replace the runtime module with a realistic legacy shim and prove that alias, structured-error, and process-URL routes never call the remote fallback resolver.

## Prevention

- Compatibility paths must preserve security policy semantics, not merely keep imports working.
- Structured error identity is part of provider routing and must be evaluated before the originally requested alias or `auto` value.
- Provider-owned policy must be resolved through the canonical profile registry so aliases cannot bypass it.
- When a compatibility shim cannot classify a candidate that may carry fail-closed policy, refusal is safer than remote fallback.
- Test compatibility branches with missing symbols and adversarial fallback targets, not only with the current full module.
