# Agy inherited indirect credential handles

**Date:** 2026-07-16 13:24
**Files:** agent/agy_cli_client.py, hermes_cli/web_server.py, tests/agent/test_agy_cli_client.py, tests/hermes_cli/test_web_oauth_dispatch.py
**Severity:** critical

## Problem

The untrusted `agy` subprocess no longer received direct AWS keys or the Claude OAuth token, but it still inherited `AWS_PROFILE`, `AWS_WEB_IDENTITY_TOKEN_FILE`, `AWS_CONTAINER_CREDENTIALS_FULL_URI`, and `SSH_AUTH_SOCK`. Those handles can resolve operator AWS credentials or use the operator's SSH agent without exposing a literal secret in the environment. Separately, the Desktop Accounts payload collapsed the external-process status to `logged_in=true` and discarded `available`, `auth_verified`, and `status_basis`.

## Root Cause

The adapter-local environment boundary enumerated only direct credential values. It assumed `inherit_credentials=False` removed all sensitive authorization capability, while the shared terminal sanitizer intentionally preserves the general AWS credential chain and operator-owned credential agents for trusted terminal children. That assumption is invalid for `agy`, because it consumes an untrusted transcript and can invoke internal tools.

The Accounts status adapter rebuilt a compatibility-shaped dictionary from the canonical provider status instead of preserving non-secret structured readiness fields. This made process availability indistinguishable from verified authentication at the Desktop boundary.

## Solution

The `agy` child boundary now removes every inherited `AWS_*` variable, removes SSH agent handles, retains the existing direct Google/Claude denylist, and sets `AWS_EC2_METADATA_DISABLED=true` so an AWS SDK cannot fall through to an instance role. Debug-level `[FIX:agy-env-boundary]` logging records only stripped variable names, never values.

The generic Accounts status adapter now conditionally carries `available`, `auth_verified`, and `status_basis` from the canonical status dictionary and emits debug-level `[FIX:external-process-status]` field-presence evidence. Regression checks cover the direct-key, profile, web-identity, container-credential, metadata, SSH-agent, and structured-status families.

## Prevention

- Treat credential pointers, local agents, metadata services, and direct secret values as equivalent capabilities at untrusted subprocess boundaries.
- Prefer family-level denial for provider namespaces that an untrusted backend never needs; exact-key lists drift as SDK credential chains grow.
- Preserve canonical non-secret status dimensions when adapting provider payloads; do not reduce availability to a compatibility boolean.
- Regression-test each credential-source family with synthetic values and assert the real child environment rather than only a sanitizer helper.
