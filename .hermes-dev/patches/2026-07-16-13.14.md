# Configured-only inventory dropped usable external-process providers

**Date:** 2026-07-16 13:14
**Files:** hermes_cli/inventory.py, hermes_cli/model_switch.py, tests/hermes_cli/test_agy_provider.py
**Severity:** high

## Problem

When the `agy` executable was available, its canonical external-process status correctly reported `configured=true`, and the full TUI inventory had real models. Desktop's configured-only model inventory nevertheless removed the row. When unconfigured rows were also requested, the usable row was replaced by an empty `authenticated=false` skeleton, so TUI Enter became a no-op and Desktop omitted `agy` until it was manually selected.

## Root Cause

External-process availability was consumed only as a temporary credential gate inside `list_authenticated_providers()`. The resulting provider row discarded that status before `build_models_payload()` applied its configured-only filter. That filter recognized current providers, user-defined endpoints, API-key/auth-store configuration, and MoA presets, but had no durable signal for a keyless process provider. It therefore filtered out the real row even though the process status and model catalog were valid.

The earlier regression covered the full unconfigured inventory and used `include_unconfigured=true` for both UI surfaces, so it did not exercise Desktop's actual `explicit_only=true` request.

## Solution

Canonical external-process rows now preserve `configured`, `auth_verified`, and `status_basis` from the shared auth-status dispatcher alongside their resolved model list. The configured-only filter retains rows carrying `configured=true`, with debug-level `[FIX:agy-provider-picker]` evidence. The behavioral regression now exercises the real split: Desktop requests `explicit_only=true`, while TUI requests the full universe, and both must receive a configured, authenticated `agy` row with its real models.

## Prevention

- Preserve non-secret provider readiness metadata across inventory stages instead of collapsing every provider into API-key semantics.
- Test each consumer with the exact request flags it uses in production; a shared payload shape does not imply shared filtering behavior.
- For keyless providers, assert the relationship between process status, configured-only visibility, authentication hints, and a non-empty model list.
- Add a neighboring regression for a future second `external_process` provider to ensure this remains provider-generic rather than `agy`-specific.
