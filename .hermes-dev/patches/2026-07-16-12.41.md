# Agy tool-loop compatibility and private @file transport

**Date:** 2026-07-16 12:41
**Files:** agent/agy_cli_client.py, agent/auxiliary_client.py, gateway/run.py, hermes_cli/runtime_provider.py, tests/agent/test_agy_cli_client.py, tests/agent/test_auxiliary_client.py, tests/run_agent/test_agy_client_integration.py, tests/gateway/test_fallback_chain_reload.py
**Severity:** critical

## Problem

The keyless `agy` provider returned every subprocess response as plain assistant content, so `<tool_call>` output never entered the Hermes tool loop. Its OpenAI-compatible facade also returned final `message` objects for `stream=True`, lacked an async auxiliary adapter, did not preserve tool-call history metadata, left active children alive after `close()`, and allowed configured fallback routes to bypass fail-closed behavior.

The first non-argv transport attempt launched `agy -p` without the required positional prompt and wrote the transcript to stdin. Real `agy 1.1.3` ignored stdin and consumed the following `--model` flag as the prompt. Passing the full transcript directly in argv exposed it through process listings and exceeded macOS `ARG_MAX` for large conversations.

## Root Cause

The adapter implemented only the smallest synchronous chat-completions surface and treated the external CLI as a cooperative one-shot subprocess. That omitted the contracts Hermes depends on: parsed OpenAI-shaped tool calls, `finish_reason="tool_calls"`, stream deltas, async conversion, owned process lifecycle, transcript metadata, and provider-level fail-closed routing.

The secure transport design assumed stdin support without validating the actual CLI grammar. The installed binary instead supports positional `@/absolute/path/prompt.txt` expansion. Missing that capability led to a false upstream blocker and a fake-process test that did not represent the real executable.

## Solution

The adapter now serializes tool schemas and `tool_choice`, parses OpenAI-shaped `<tool_call>` blocks, returns typed tool calls with the correct finish reason, preserves assistant/tool metadata, emits OpenAI delta chunks, exposes a thread-backed async facade, owns and terminates its active process group, and refuses auxiliary or cached-gateway fallback chains for the fail-closed agy route.

Each attempt writes the formatted transcript to an exclusive private `0600` file inside its isolated request workspace and passes only the absolute `@file` reference to `agy -p`. Cleanup runs in `finally`, including timeout and spawn-failure paths. Regression tests cover permissions, cleanup, large transcripts, argv non-disclosure, tool-loop execution, stream/async/lifecycle behavior, and fail-closed refresh. A live `agy 1.1.3` probe returned `AGY_FILE_PROMPT_OK` with exit 0 while `ps` showed only the `@file` reference and not the payload.

Auxiliary auth refresh preserves its explicit environment-call contract, and the Codex auxiliary total-timeout deadline now starts at function entry. Its regression test asserts early stream termination rather than a scheduler-sensitive wall-clock threshold.

## Prevention

- Validate external-process grammar against the installed real binary before choosing stdin, argv, or file transport.
- For sensitive large prompts, prefer exclusive `0600` file indirection with containment checks and unconditional cleanup when the CLI supports `@file` expansion.
- Every OpenAI-compatible process adapter should test sync, async, stream delta, tool calls, tool-result history, cancellation, and close semantics through the real Hermes loop.
- Fail-closed provider policy must be enforced at initialization, auxiliary fallback, runtime fallback activation, and cached-agent refresh.
- Timeout tests should assert behavioral interruption or bounded work, not tight wall-clock thresholds that fail under scheduler load.
